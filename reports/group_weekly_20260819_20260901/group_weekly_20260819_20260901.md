## 01 · DrawingPT v0 数据资产与训练闭环

**状态：smoke 完成，进入类别均衡诊断。**

**本期结论：** DrawingPT v0 已从设计草案推进到服务器 GPU 可运行闭环，但 1% semantic smoke 暴露出高频类塌缩。

- 生成并冻结 FloorPlanCAD primitive token manifest：11,602 张 SVG，共 12,621,288 个 primitive token；按 2048 token/window 得到 14,117 个 window。
- 固定 1%、5%、10%、25%、50%、100% train 低标注清单，seed 为 304、1004、2026；同一 seed 下小比例是大比例前缀，便于后续 label-efficiency curve 对比。
- 补齐 Dataset、masked primitive pretrain、semantic primitive classification 三个最小训练入口；服务器 processed SVG 布局也已兼容。
- 服务器完成 2048-token masked pretrain short：100 step，loss 1.642630 降到 0.107217，生成 checkpoint SHA-256 ceb52ad65ae94c69a9b0409fb2404b875f33a2de6975d5190862efb09d50317e。
- semantic scratch 诊断证明 class 0=background/unlabeled 参与 loss 会导致 all accuracy 虚高但 foreground F1 为 0；之后改成 foreground-only loss。
- foreground-only scratch/pretrained/weighted smoke 都已跑通；weighted scratch 将 foreground macro F1 从 0.0168 小幅提高到 0.0209，下一步处理 wall/window/sink 高频类主导的问题。

**1% semantic smoke 对比：** 同一 1% seed0304、2048-token window、100 step；这些是轻量 smoke 指标，用来判断链路和训练目标。

| job | 设置 | foreground accuracy | foreground macro F1 | 判断 |
| --- | --- | --- | --- | --- |
| 1406 | background 参与 loss | 0.0000 | 0.0000 | 诊断：background shortcut |
| 1407 | foreground-only scratch | 0.3391 | 0.0168 | 开始命中前景，但偏 wall/sink |
| 1409 | foreground-only pretrained | 0.3412 | 0.0177 | 略高于 scratch，但差距太小 |
| 1411 | inverse-sqrt weighted scratch | 0.2512 | 0.0209 | macro F1 略升，准确率下降 |
| 1412 | inverse-sqrt weighted pretrained | 0.2931 | 0.0141 | 低于 weighted scratch |

**本期方法创新点：**

- 把 SVG primitive 直接作为 DrawingPT v0 token，统一记录 type、semanticId、instanceId、bbox、长度 proxy、面积 proxy 和弱样式特征。
- 把自监督预训练和低标注语义微调接到同一个 Dataset/manifest 上，后续可以做 scratch vs pretrained 的 label-efficiency curve。
- 把诊断结果结构化记录：background shortcut、checkpoint 安全加载兼容性、weighted loss 对宏平均和前景准确率的 trade-off 都留下了 evidence。

*表述边界：当前创新点是实验链路和表示设计层面的 v0 prototype；SOTA 比较放到低标注曲线稳定后再做。*

**可信边界：** 所有 semantic 数字只来自 1% seed0304、100 step、128 个 validation window 的 smoke；当前只支持训练闭环和失败模式判断，预训练有效性要等低标注曲线验证。

**下一门禁：** 实现 class-aware window sampling 或 focal loss，在同一 1% seed0304 下重跑 scratch vs pretrained；若 foreground macro F1 明显高于 0.0209 且不再塌到 wall/window/sink，再扩到 5%、10% 和多个 seed。

## 02 · 工程造价方向与 pseudo-BoQ 中间层

**状态：调研完成，工程量 proxy 已冻结。**

**本期结论：** 造价方向被收束为“图纸理解 → 工程量 proxy → BoQ/造价”的可解释链路，而不是直接黑箱预测总价。

- 完成工程造价自动估算调研：成熟路线主要是 BIM/结构化工程量到造价，或历史项目特征到造价预测；2D CAD 原始图元直接到完整造价的成熟学术路线还少。
- 明确 DrawingPT 的短期定位：作为图纸理解和表示学习前端，先抽取构件、符号、尺寸/数量关系，再服务 quantity takeoff、BoQ/BoM 和造价模型。
- 生成 FloorPlanCAD pseudo-BoQ 每图表，共 11,602 行；字段包括门窗数量、墙体/幕墙/栏杆长度 proxy、楼梯/电梯/扶梯数量、车位和厨卫设备等。
- 训练集汇总可讲数字包括：门 instance 34,704，窗 instance 15,376，墙体长度 proxy 8,836,841.492，楼梯 instance 4,345，电梯 instance 3,206，厨卫设备 instance 16,722。

| 指标 | 本期值 |
| --- | --- |
| pseudo-BoQ rows | 11,602 |
| train door instances | 34,704 |
| train window instances | 15,376 |
| train wall length proxy | 8,836,841.492 |
| train sanitary fixture instances | 16,722 |

**造价相关路线成熟度判断：** 该比较来自本期文献调研和 FloorPlanCAD 数据资产审计。

| 路线 | 成熟度 | 对 DrawingPT 的含义 |
| --- | --- | --- |
| BIM / 结构化工程量 → 造价 | 较高 | 可作为后端流程和评价口径参考 |
| 项目特征 / 历史数据 → 总造价 | 中高 | 适合早期估算，但不验证图纸表示学习 |
| 2D 图纸 → 符号 / 构件 / BoM / QTO | 中等 | 与 DrawingPT 最相关，适合作为近期研究任务 |
| 2D CAD 原始图元 → 完整真实造价 | 低到中 | 有创新空间，但需要真实 BoQ/单价/成本标签 |

**本期方法创新点：**

- 把造价目标拆成可验证中间层：先用图纸语义预测生成 pseudo-BoQ，再讨论造价映射。
- 每个工程量 proxy 都能追溯到 FloorPlanCAD 的 semanticId、instanceId 和几何长度 proxy，避免端到端黑箱总价不可解释。
- 为后续模型评估准备了比 F1 更接近应用的误差口径：count MAE、relative error、length proxy error。

*表述边界：pseudo-BoQ 是研究 proxy，当前用于验证工程量中间层；真实工程结算量需要单位、材料做法和价格信息。*

**可信边界：** 当前成果定位为工程量中间层：比例尺、墙高/厚度、材料、楼层、地区定额、单价和项目造价标签是后续接真实造价所需资源。

**下一门禁：** 等 semantic prediction 稳定后，把预测结果转成同字段 pseudo-BoQ，与 GT pseudo-BoQ 计算 count MAE、count relative error 和 length relative error；如需要演示造价链路，可先做合成单价 demo，并明确它不是真实造价。

## 03 · CADTransformer PQ/SQ/RQ 评估门禁

**状态：门禁审计完成，下一步路线可选。**

**本期结论：** CADTransformer 已可作为 semantic baseline；PQ/SQ/RQ 进入 official/proxy 评估链路补齐阶段。

- 审计 CADTransformer 当前 release：README 提到的 scripts/evaluate_pq.py 需要另行找回或重建。
- 确认当前 train_cad_ddp.py 的 val/test 入口输出 primitive-level Total FG Precision/Recall/F1；prediction export 需要单独补脚本。
- 确认当前模型入口主要返回 semantic logits；panoptic instance prediction/export/evaluation 需要作为独立评估链路补接。
- 因此保留 job 969 的 Total FG F1=0.827501 作为 semantic primitive baseline 锚点，但不把它与论文 PQ/SQ/RQ 直接相减。

*表述边界：这是评估链路审计；它的作用是明确后续比较口径。*

**可信边界：** 当前 CADTransformer 在本周报中定位为 semantic baseline；paper-faithful 主指标需要 official evaluation/export 或透明 proxy 口径后再汇报。

**下一门禁：** 组会上需要决策：是否必须优先追官方 PQ/export。如果必须，下一步找历史 commit、issue 或联系作者；如果可以并行推进，则先把 CADTransformer 作为 semantic baseline，用 DrawingPT v0 跑 label-efficiency curve。
