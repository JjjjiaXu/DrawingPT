FloorPlanCAD 数据画像与长尾风险

FloorPlanCAD 的核心风险不是数据量小，而是图元形态和语义类别都高度长尾：这直接解释了为什么 1% smoke 会被 wall/window/sink 主导。

本期新增

  1. 补齐全量 11,602 张 SVG 的 raw primitive、semantic element、instance 和 split 级统计，用于回答“数据到底长什么样”。
  2. raw SVG primitive 共 12,621,288 个，其中 path 12,454,181 个，占 98.68%；circle 157,009 个，占 1.24%；ellipse 10,098 个，占 0.08%。
  3. 单图 primitive 数中位数为 544、均值为 1,087.85、p95 为 3,541、最大值为 53,919；另有 79 张图超过 10,000 个 primitive，说明按整图训练会被长尾大图拖住。
  4. 带 semanticId 的元素共 5,828,994 个，35 类全量均出现；最大类 wall 有 1,362,387 个，占 23.37%，而 rolling door 只有 98 个，占 0.0017%。
  5. val split 只覆盖 33/35 类，缺少 revolving door 和 rolling door；因此 rare-class 指标不能只看单个小验证集，需要记录 per-class support 和多 seed。

数据画像如何影响实验设计

这些统计把“为什么要窗口化、为什么要 class-aware、为什么不能只看 overall F1”变成可解释的实验约束。

观察关键数字对实验的含义
图元形态单一path 占 98.68%v0 先把 path 几何编码做稳，比过早追求复杂 DWG 结构更实际
单图规模长尾中位数 544，最大值 53,919需要 2048-token window 和大图切窗策略，不能假设每张图复杂度接近
语义类别长尾wall 23.37%，rolling door 0.0017%low-label 实验必须报告 macro/rare F1，且采样要主动覆盖稀有类
验证集稀有类缺失val 覆盖 33/35 类rare-class 结论要结合 per-class support 和多 seed，避免把验证集缺类误读为模型能力

数据画像带来的方法收束

  • 把 DrawingPT v0 的第一阶段重点明确为 primitive-level 表示学习，而不是直接追完整 CAD/DWG 语义层级。
  • 把 class-aware sampling 从“可选优化”提升为下一轮实验门禁，因为当前类别分布会天然奖励高频类预测。
  • 把 evaluation 从单一 foreground accuracy 改成 foreground macro F1、rare-class F1、per-class support 三件套。

表述边界这是数据与评估设计证据，不是模型效果证据；它解释实验风险和下一步设计合理性。

可信边界统计基于公开 11,602 张 SVG baseline split；FloorPlanCAD 官网后续提到的 15,663 张版本不在本轮 baseline 内。SVG primitive 统计不恢复 DWG block/layer/topology，length proxy 也不是米或平方米。

造价相关路线成熟度判断

该比较来自本期文献调研和 FloorPlanCAD 数据资产审计。

路线成熟度对 DrawingPT 的含义
BIM / 结构化工程量 → 造价较高可作为后端流程和评价口径参考
项目特征 / 历史数据 → 总造价中高适合早期估算，但不验证图纸表示学习
2D 图纸 → 符号 / 构件 / BoM / QTO中等与 DrawingPT 最相关，适合作为近期研究任务
2D CAD 原始图元 → 完整真实造价低到中有创新空间，但需要真实 BoQ/单价/成本标签

本期方法创新点

  • 把造价目标拆成可验证中间层：先用图纸语义预测生成 pseudo-BoQ，再讨论造价映射。
  • 每个工程量 proxy 都能追溯到 FloorPlanCAD 的 semanticId、instanceId 和几何长度 proxy，避免端到端黑箱总价不可解释。
