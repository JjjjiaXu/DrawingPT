DrawingPT v0 数据资产与训练闭环

DrawingPT v0 已从设计草案推进到服务器 GPU 可运行闭环，但 1% semantic smoke 暴露出高频类塌缩。

本期新增

  1. 生成并冻结 FloorPlanCAD primitive token manifest：11,602 张 SVG，共 12,621,288 个 primitive token；按 2048 token/window 得到 14,117 个 window。
  2. 固定 1%、5%、10%、25%、50%、100% train 低标注清单，seed 为 304、1004、2026；同一 seed 下小比例是大比例前缀，便于后续 label-efficiency curve 对比。
  3. 补齐 Dataset、masked primitive pretrain、semantic primitive classification 三个最小训练入口；服务器 processed SVG 布局也已兼容。
  4. 服务器完成 2048-token masked pretrain short：100 step，loss 1.642630 降到 0.107217，生成 checkpoint SHA-256 ceb52ad65ae94c69a9b0409fb2404b875f33a2de6975d5190862efb09d50317e。
  5. semantic scratch 诊断证明 class 0=background/unlabeled 参与 loss 会导致 all accuracy 虚高但 foreground F1 为 0；之后改成 foreground-only loss。
  6. foreground-only scratch/pretrained/weighted smoke 都已跑通；weighted scratch 将 foreground macro F1 从 0.0168 小幅提高到 0.0209，下一步处理 wall/window/sink 高频类主导的问题。

  • 把 SVG primitive 直接作为 DrawingPT v0 token，统一记录 type、semanticId、instanceId、bbox、长度 proxy、面积 proxy 和弱样式特征。
  • 把自监督预训练和低标注语义微调接到同一个 Dataset/manifest 上，后续可以做 scratch vs pretrained 的 label-efficiency curve。
  • 把诊断结果结构化记录：background shortcut、checkpoint 安全加载兼容性、weighted loss 对宏平均和前景准确率的 trade-off 都留下了 evidence。

可信边界所有 semantic 数字只来自 1% seed0304、100 step、128 个 validation window 的 smoke；当前只支持训练闭环和失败模式判断，预训练有效性要等低标注曲线验证。

本期新增

  1. 完成工程造价自动估算调研：成熟路线主要是 BIM/结构化工程量到造价，或历史项目特征到造价预测；2D CAD 原始图元直接到完整造价的成熟学术路线还少。
  2. 明确 DrawingPT 的短期定位：作为图纸理解和表示学习前端，先抽取构件、符号、尺寸/数量关系，再服务 quantity takeoff、BoQ/BoM 和造价模型。
  3. 生成 FloorPlanCAD pseudo-BoQ 每图表，共 11,602 行；字段包括门窗数量、墙体/幕墙/栏杆长度 proxy、楼梯/电梯/扶梯数量、车位和厨卫设备等。
  4. 训练集汇总可讲数字包括：门 instance 34,704，窗 instance 15,376，墙体长度 proxy 8,836,841.492，楼梯 instance 4,345，电梯 instance 3,206，厨卫设备 instance 16,722。

造价相关路线成熟度判断

该比较来自本期文献调研和 FloorPlanCAD 数据资产审计。

路线成熟度对 DrawingPT 的含义
BIM / 结构化工程量 → 造价较高可作为后端流程和评价口径参考
项目特征 / 历史数据 → 总造价中高适合早期估算，但不验证图纸表示学习
2D 图纸 → 符号 / 构件 / BoM / QTO中等与 DrawingPT 最相关，适合作为近期研究任务

本期方法创新点

  • 把造价目标拆成可验证中间层：先用图纸语义预测生成 pseudo-BoQ，再讨论造价映射。
  • 每个工程量 proxy 都能追溯到 FloorPlanCAD 的 semanticId、instanceId 和几何长度 proxy，避免端到端黑箱总价不可解释。
  • 为后续模型评估准备了比 F1 更接近应用的误差口径：count MAE、relative error、length proxy error。

表述边界pseudo-BoQ 是研究 proxy，当前用于验证工程量中间层；真实工程结算量需要单位、材料做法和价格信息。

可信边界当前成果定位为工程量中间层：比例尺、墙高/厚度、材料、楼层、地区定额、单价和项目造价标签是后续接真实造价所需资源。
